# Tesla Road Trip Game UI Pages

This document describes the current browser UI so another AI/team can design an alternate implementation with equivalent behavior.

## Global UI model

The web app is mostly a single-page application served from `static/index.html` with behavior in `static/game.js`.

Primary routes:

- `/` or `/index.html` — main game app. It contains both the session-selection screen and the in-game dashboard.
- `/?sessionId=<id>` — opens the main app and attempts to auto-join that session.
- `/config-builder.html` — visual map/configuration builder.
- `/llms.txt` — plain-text guide for AI/LLM players.
- `/playground` — GraphQL playground generated by gqlgen.
- `/graphql` — GraphQL API endpoint used by the UI.
- `/ws?session=<session_id>` — WebSocket endpoint used for live game-state updates.

Visual style is Tesla-inspired: clean white/gray surfaces, Inter font, large light-weight numerals, subtle shadows, rounded panels, and emoji-based game pieces.

Core game icons:

- `🚗` active player car
- `🚙`, `🏎️`, `🚘`, etc. observer/other-player cars
- `💥` crashed/game-over car
- `🏠` home/charging tile
- `🌳` park/objective tile
- `⚡` supercharger tile
- `💧` water obstacle
- `🏢` building obstacle
- blank/white cell = road

## Page 1: Main app — session selection screen

Route: `/` before a session is selected, or after clicking **Switch Session**.

Purpose: lets the player choose a map configuration, preview it, optionally resume an existing session, then enter the game dashboard.

### Layout

Full-screen centered modal-style panel over a light gray gradient background.

The main card contains:

1. **Header**
   - Title: `Tesla Road Trip Game`
   - Subtitle: `Pick a configuration and play`

2. **Configuration selector**
   - A dropdown populated from the GraphQL `configs` query.
   - Each option shows the config name and description.
   - Selecting a config refreshes the preview panel.

3. **Configuration details area**
   - The code has support for a detailed configuration list with expandable config cards, though the session screen primarily emphasizes the preview.

4. **Live preview card**
   - Header with `Preview` label.
   - Stats line showing:
     - grid dimensions, e.g. `20×20`
     - starting/max battery, e.g. `Battery: 20/20`
     - number of parks, e.g. `Parks: 10`
   - Mini grid rendering of the selected layout.
   - Legend:
     - Home/Charging
     - Parks to Collect
     - Supercharger
     - Obstacles

5. **Resume session input**
   - Label: `Resume session (optional):`
   - Text input for a session ID.
   - If provided, pressing Play resumes that session instead of creating a new one.

6. **Play button**
   - Large green button: `▶ Play`
   - If resume ID is empty, creates a new session using selected configuration.
   - If resume ID is filled, loads that existing session.

7. **Error message area**
   - Hidden by default.
   - Shows red error panel for session creation/load failures.
   - Auto-hides after about 5 seconds.

8. **Footer links**
   - `🗺️ Create Custom Map` linking to `/config-builder.html`
   - `🤖 LLM API Guide` linking to `/llms.txt`

### Behavior

- On DOM ready, the UI loads available configurations.
- The first config is selected by default.
- When the selected config changes, the preview and stats update.
- Starting a game hides this screen and displays the dashboard.
- If URL has `?sessionId=...`, the app skips manual selection and tries to load that session automatically.

## Page 2: Main app — active game dashboard

Route: `/` after creating/resuming a session.

Purpose: primary gameplay interface. Shows the map, player state, other players, and control hints.

### Overall layout

Two-column full-height dashboard:

- **Left side:** map/grid area.
- **Right side:** control/status panel.
- Fixed connection badge in the top-right corner.
- Floating gear button on the right edge opens the slide-out menu.

### Connection badge

Fixed top-right label:

- `Connected` in green when active WebSocket is connected.
- `Disconnected` in red when not connected.

### Left map section

Contains the game board and cave-mode controls.

#### Game grid

- Rendered as an HTML table.
- Cell classes are based on cell type: road, home, park, supercharger, water, building.
- Special tiles display emoji icons.
- Visited parks are dimmed/faded.
- Active player car is rendered over the grid:
  - `🚗` normally
  - `💥` if game over
  - larger than observer cars
  - red glow/drop shadow
- Other players are rendered as smaller semi-transparent cars with distinct icons/colors.
- Trails can be rendered as small colored dots if trail data exists.

#### Cave Mode controls

Below the grid:

- Checkbox: `Cave Mode (Radius: N)`
- Range slider, min 1, max 5 in the dashboard control.

Cave Mode behavior:

- When enabled, cells outside the player's Chebyshev-distance radius are darkened/hidden.
- Newly visible cells animate with a reveal effect.
- Settings are stored in `localStorage`.
- A second Cave Mode control exists in the slide-out menu and is synchronized with this one.

### Right control panel

#### Header

- Title: `Tesla Road Trip`
- Blue `Switch Session` button
  - Disconnects WebSockets.
  - Clears active session state.
  - Returns to session selection screen.

#### Active session panel

Red-bordered/light-red panel showing the controlled session.

Contains:

1. **Panel title**
   - `YOUR SESSION`
   - Session ID badge, e.g. `23d1`

2. **Stats cards**
   - Battery card:
     - label `Battery`
     - value like `14/20`
     - horizontal battery bar
     - bar color:
       - green when >50%
       - orange when >25%
       - red when <=25%
   - Parks card:
     - label `Parks`
     - value like `3/10`
   - Moves card:
     - label `Moves`
     - total move count

3. **Status/message box**
   - Shows game-state message, for example:
     - `Ready to drive`
     - `Park visited! Score: 3`
     - `You crashed into a wall! Game Over! [Hit: building at (4,11)]`

4. **Keyboard hint bar**
   - Purple gradient bar.
   - Text: `🎮 Arrow Keys or WASD to move • R to reset`

#### Other Players panel

Shows observer sessions with the same configuration.

Contains:

- Title: `OTHER PLAYERS`
- Refresh icon/button `↻`
- List of other sessions, each with:
  - car icon
  - session ID
  - battery, e.g. `⚡12/20`
  - score/parks, e.g. `🌳10`
  - move count, e.g. `📍129 moves`

If no observer sessions exist, shows `No other players`.

The list auto-refreshes about every 10 seconds while dashboard is active.

#### Configuration info panel

Small panel showing:

- Label: `CONFIGURATION`
- Active config name, e.g. `classic`

### Keyboard controls

Only active while dashboard is visible and a session is loaded.

- Arrow Up / `W` = move up
- Arrow Down / `S` = move down
- Arrow Left / `A` = move left
- Arrow Right / `D` = move right
- `R` = reset current session

Moves and reset are sent via GraphQL mutations. The UI relies on WebSocket updates to refresh the displayed state.

### Realtime behavior

- Active session connects to `/ws?session=<activeSessionId>`.
- Observer sessions each get their own WebSocket connection.
- Active-session state updates are queued and animated with roughly 500ms between state renders.
- Observer updates are applied immediately unless the active session animation queue is running.
- WebSocket disconnects trigger reconnect attempts.

## Page 3: Slide-out right menu

Accessible from the floating gear button `⚙️` on the main app.

Purpose: secondary controls, AI/remote-control help, and duplicate Cave Mode settings.

### Layout

- Fixed panel slides in from the right.
- Width about 400px.
- Scrollable vertically.
- Header:
  - Title: `Controls & AI`
  - Subtitle: `Remote control and AI assistance`

### Sections

#### Integration & Remote Control

- Gradient card inviting users to connect with GraphQL, MCP, and AI assistants.
- Link/button: `📚 View Integration Guide`
  - Current href is `/integration`.
- Quick-start code block with example curl commands.

Note: the text in this section references `/graphql` as if it accepts REST-like calls in a few examples. The current UI itself uses GraphQL POST requests with query/mutation payloads.

#### Cave Mode

Secondary Cave Mode controls:

- Toggle switch: `Enable Cave Mode`
- Radius slider, shown as `Visibility Radius: N cells`
- Labels: `Close`, `Medium`, `Far`
- Explanation text: fog-of-war mode where only immediate surroundings are visible.

This is synchronized with the dashboard Cave Mode checkbox/slider.

#### AI Assistant Prompt

- Textarea labeled `Your Task:` with editable prompt task text.
- Collapsible `System Prompt` details element.
- Large prewritten prompt describing game rules, API usage, strategy, endpoints, and victory conditions.
- JavaScript has a `copyPrompt` function intended to copy the combined prompt and task to clipboard, with temporary button feedback, though the visible button markup should be verified when redesigning.

## Page 4: Map Configuration Builder

Route: `/config-builder.html`

Purpose: lets users create or edit custom game map configurations visually.

### Overall layout

Large centered white builder container with:

- Purple header bar.
- Two-column content area on desktop:
  - Left: grid editor.
  - Right: settings panel.
- Responsive layout stacks sections on smaller screens.

### Header

- Title: `🗺️ Map Configuration Builder`
- Subtitle exists in markup but is hidden by CSS.

### Left grid editor section

#### Editable grid

- HTML table with square cells.
- Default size: 10×10.
- Each cell displays based on current type:
  - `R` Road: blank/white
  - `H` Home: `🏠`
  - `P` Park: `🌳`
  - `S` Supercharger: `⚡`
  - `W` Water: `💧`
  - `B` Building: `🏢`
- Clicking/tapping a cell paints it with the currently selected tool.
- Hovering cells enlarges them slightly on desktop.

#### Grid controls

Below the grid:

1. **Load Config dropdown**
   - First option: `-- New Configuration --`
   - Populated from GraphQL configs.
   - Selecting an existing config loads it into edit mode.

2. **Grid Size dropdown**
   - Options: 5×5, 8×8, 10×10, 15×15, 20×20, 25×25, 30×30.
   - Changing size asks for confirmation and clears current data.

3. **Fill Roads button**
   - Sets every cell to road.

4. **Fill Buildings button**
   - Sets every cell to building.

5. **Clear All button**
   - Confirms, then fills roads.

6. **Validation message area**
   - Hidden until validate/load/save feedback is needed.
   - Supports success, warning, and error styles.

### Right settings panel

#### Cell Type Palette

Grid of selectable paint tools:

- Road (R)
- Home (H)
- Park (P)
- Supercharger (S)
- Water (W)
- Building (B)

The selected tool is highlighted and shown as `Current tool: ...`.

#### Map Statistics

Four stat boxes update as the grid changes:

- Parks
- Homes
- Superchargers
- Obstacles — combined water + buildings

#### Configuration Settings

Form fields:

- **Map Name***
  - Required.
  - Helper says lowercase and underscores.
  - Read-only when editing an existing config.
- **Description** textarea.
- **Max Battery** number input, min 5, max 100.
- **Starting Battery** number input, min 5, max 100.
- **Wall crash ends game** checkbox.

#### Action buttons

- `✓ Validate Map`
- `💾 Save Configuration` or `💾 Update Configuration` when editing
- `← Back to Game` linking to `/`

### Builder validation behavior

Current browser-side validation checks:

- At least one park is required.
- At least one home is required.
- Map name is required.

If validation passes, it shows `✅ Map is valid and ready to save!`.

### Save behavior

On save:

- Builds a configuration object from form fields and grid data.
- Generates default message templates.
- Sends a GraphQL `createConfig` mutation.
- Shows success message.
- Redirects to `/` after about 2 seconds.

## Page 5: LLM API guide

Route: `/llms.txt`

Purpose: plain text instructions for AI agents/LLMs that want to play the game programmatically.

Expected content:

- GraphQL endpoint and playground references.
- Session creation instructions.
- Queries/mutations for game state, movement, reset, configs, and history.
- Cell type explanations.
- Strategy tips for LLM players.

This page is not an interactive UI; it is documentation optimized for machine reading.

## Page 6: GraphQL Playground

Route: `/playground`

Purpose: developer-facing interactive GraphQL explorer.

Behavior:

- Served by gqlgen's playground handler.
- Points to `/graphql`.
- Allows developers/AI builders to inspect and run queries/mutations manually.

This page is not styled like the game; it uses the standard GraphQL playground UI.

## Equivalent implementation requirements

An alternate implementation should preserve these product behaviors even if the layout and technology change:

1. Users can select a configuration, preview the map, and start a new session.
2. Users can resume a session by ID.
3. Users can auto-join via `?sessionId=<id>`.
4. Users can see the active game grid with terrain, objectives, chargers, player car, crashes, and visited parks.
5. Users can move with Arrow keys or WASD.
6. Users can reset with `R`.
7. Users can monitor battery, parks collected, move count, current message, session ID, and config name.
8. Users can switch sessions and return to the selection screen.
9. The UI shows live updates through WebSockets.
10. Other active sessions on the same config are discoverable and visible as observer players.
11. Cave Mode/fog of war can be toggled and radius-adjusted, with settings persisted locally.
12. Users can create/edit custom maps visually, validate them, and save them.
13. Users can access AI/developer guidance through `/llms.txt`, the slide-out menu, and `/playground`.

## Data the UI depends on

The alternate implementation needs equivalent access to:

- Config list: names, descriptions, IDs/filenames, grid size, battery settings.
- Full config: layout rows, wall-crash rule, messages.
- Session: ID, config name, created/last-accessed timestamps.
- Game state:
  - grid cell type/visited/id
  - player position
  - battery and max battery
  - score
  - visited parks
  - message
  - game-over and victory flags
  - config name
  - move history / total moves
  - optional local view / battery-risk helper data
- Realtime session state updates over WebSocket.
